# 기능 보존 acceptance matrix

초기 Gemini판의 설계 작업이 현행 비선형 모델·실부품 선택·13개 토폴로지 위에서 복구됐는지 판정하는 문서입니다. 추적 이슈는 [#21](https://github.com/InitusNovus/led-tr-analyzer/issues/21), 검증 게이트는 [#29](https://github.com/InitusNovus/led-tr-analyzer/issues/29)입니다.

테스트 통과, coverage, 화면 캡처 수만으로 기능이 복구됐다고 판정하지 않습니다. 각 행은 구현 PR이 증거(테스트 파일, 스크린샷)를 붙여 갱신하며, **결정**이 `대기`인 행이 남아 있으면 #21을 닫지 않습니다.

결정 값: `복구` · `동등 대체` · `의도적 제외` · `후속 이관` · `대기`

## 3. PR 증거 규칙

- 각 PR은 해당 child 이슈와 관련 G 시나리오를 본문에 명시하고, 실제로 만족한 acceptance criteria만 체크합니다.
- 상위 이슈는 `Refs #21`로만 연결합니다. 모든 P1 항목, #28의 처리 결론, #29 게이트가 끝나기 전에는 `Closes #21`을 쓰지 않습니다.
- 위 표의 `현재 상태`, `결정`, `증거`는 해당 PR에서 함께 갱신합니다.
- 연결을 일부러 끊었을 때(예: 적용 시 목표 보존 코드 제거) 해당 시나리오가 실패하는지 #29 PR에서 확인합니다.
